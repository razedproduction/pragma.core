# Решения проекта pragma.core

ADR-лог. Решение меняется только новой записью с причиной (старую не удаляем, помечаем «заменено #N»).

| # | Решение | Выбор | Почему | Дата |
|---|---------|-------|--------|------|
| 1 | Границы ядра | Runtime-ядро: base + sync + jobs + граф кадра + async. **Без** ECS, рендера, окна, App/плагинов | Ядро должно годиться для разных движков и фреймворков; ECS и цикл кадра — решения конкретного движка, строятся поверх | 2026-10-13 |
| 2 | Платформы | Windows и Linux (x86_64), обе в CI | Текущие цели. macOS/wasm/мобильные вне скоупа; API не должен исключать однопоточный fallback (нужен для wasm без atomics), но и не реализует его | 2026-10-13 |
| 3 | Аудитория | Свои инди-проекты с заделом на профессиональное использование | Простой API сейчас; «профи»-гарантии (детерминизм, semver-checks, бенч-гейт, MSRV) вводятся поэтапно и обязательны к v1.0 — см. roadmap | 2026-10-13 |
| 4 | Чистота зависимостей | Только pure Rust; системные FFI (`windows-sys`, `libc`) допустимы | Воспроизводимая сборка, кросс-компиляция, аудит. Проверка: `cargo deny`, `tools/audit_workspace.py` | 2026-10-13 |
| 5 | Lock-free основа | `crossbeam-deque` / `crossbeam-utils` вместо своих lock-free структур | Проверенный годами pure-Rust код; собственный Chase-Lev deque — месяцы верификации ради единиц процентов | 2026-10-13 |
| 6 | Политика `unsafe` | `#![forbid(unsafe_code)]` везде, кроме `pragma_sync`; там — `// SAFETY:` на каждый блок, Miri + loom в CI | Локализует риск в одном маленьком крейте, который реально можно проверить | 2026-10-13 |
| 7 | Исключение чистоты | `generator` (тянет `cc`) через `loom` — принят (уточнено #12) | Только dev-зависимость под `cfg(loom)`, в бинарники пользователей не попадает; `deny.toml` исключает dev-граф | 2026-10-13 |
| 8 | Async-исполнитель | `async-task` + `futures-lite`, без tokio | Ядру нужен исполнитель, а не сетевой реактор; tokio — второй пул потоков и тяжёлые зависимости. Выбор I/O-модели — на вехе M3 | 2026-10-13 |
| 9 | Паники в задачах | Перехват `catch_unwind` в воркере, возврат как ошибки из `join`/хэндла | Паника пользовательского кода не убивает воркер и не вешает ожидающих. При `panic = "abort"` процесс падает — это задокументировано | 2026-10-13 |
| 10 | Тулчейн | Edition 2024, MSRV 1.88 (минимум для proptest), закреплён 1.99.0 | Одинаковые результаты clippy локально и в CI; MSRV проверяется отдельным джобом | 2026-10-13 |
| 11 | Язык | README — английский; `docs/`, `DECISIONS.md`, rustdoc — русский | README виден снаружи; внутренняя документация — на рабочем языке автора. Пересмотреть перед публикацией на crates.io | 2026-10-13 |
| 12 | `loom` в `pragma_sync` | `[target.'cfg(loom)'.dependencies]` вместо dev-зависимости; loom-джоб: `cargo test -p pragma_sync --release --lib --tests` | Библиотека сама импортирует модели loom (`src/primitives.rs`), иначе модель-чекер не видит её атомиков. Без `--cfg loom` зависимость не активируется; `deny.toml` проверяет граф только для `x86_64-pc-windows-msvc`/`x86_64-unknown-linux-gnu`, где `cfg(loom)` ложен. Доктесты исключены из loom-прогона: они работают с реальными потоками вне `loom::model` | 2026-10-13 |
| 13 | Ошибки `pragma_jobs` | Два enum: `JobsError` (создание пула) и `JobError` (исход задачи) | Исход задачи нужно клонировать, сравнивать и пересылать между потоками, а `JobsError` несёт `std::io::Error` (не `Clone`). Исключение из правила «один enum на крейт» (`docs/reliability.md` §2) | 2026-10-13 |
| 14 | Эталон в бенчах | `rayon` — только dev-зависимость `pragma_jobs` | Сравнение накладных расходов с индустриальным стандартом (roadmap M1). В граф пользователей не попадает (`deny.toml: exclude-dev`) | 2026-10-13 |
| 15 | `unsafe` для `scope`/`join` | Стирание лайфтайма задач области и задача-в-слоте на стеке (`StackSlot`) — только в `pragma_sync` (`scope.rs`) | `pragma_jobs` остаётся `forbid(unsafe_code)`: ему отдаётся безопасный API, где `scope()` не возвращается, пока не завершены все задачи (паника в ожидании → `abort`). `StackSlot` убирает `Box` из `join`: на системном аллокаторе Windows аллокация (~90 нс) дороже самого `join` | 2026-10-13 |
| 16 | Главный поток в пуле | Внешние слоты: 4 LIFO-очереди, которые поток вне пула занимает на время `scope`/`join`/`JobHandle::join` | Через FIFO-injector помощь в ожидании брала бы самые старые задачи и наращивала стек квадратично (fib(20) переполнял стек в debug). Внешний поток не берёт `Background`, чтобы не застрять в запекании посреди кадра | 2026-10-13 |
| 17 | Исключение чистоты | `alloca` (собирает C через `cc`) через `criterion` 0.8 — принят | Безусловная зависимость `criterion` на Windows/Unix (варьирует стек при замерах), фичей не отключается. Только dev-зависимость бенчей `pragma_jobs`; `deny.toml` исключает dev-граф, `layers.toml` — `[purity.accepted]` | 2026-10-13 |
| 18 | Кадр графа без аллокаций | Dataflow на `ArrivalCounter` (`pragma_sync`): готовые задачи запускаются через `join` (слот на стеке), а не `spawn`; весь кадр — одна `scope`. Контекст внешнего слота пула кэшируется в потоке; кэш счётчиков областей переиспользует счётчик при нуле, не требуя `strong_count == 1` | `spawn` и `Scope::spawn` аллоцируют `Box` на задачу (~90 нс на Windows). Каждый вход главного потока в пул создавал `Rc<WorkerCtx>`, а гонка «счётчик уже ноль, клон `Arc` ещё жив у хвоста `decrement`» опустошала кэш счётчиков (~1 аллокация на кадр). После нуля хвост `decrement` счётчик не меняет — лишнее пробуждение ожидающих безвредно. Кэшированный контекст держит `Arc<Shared>` последнего пула до следующего входа (только память, потоки пула не задерживаются) | 2026-10-13 |
| 19 | `unsafe` в тесте `pragma_graph` | Считающий `GlobalAlloc` в `tests/alloc.rs` (делегирует `System`) | Критерий M2 «кадр без аллокаций» проверяется машиной только глобальным аллокатором. Код тестовый, в библиотеку не попадает; альтернатива — внешний крейт ради 20 строк | 2026-10-13 |
| 20 | Исключение чистоты | `libfuzzer-sys` (C++ libFuzzer) — только в отдельном workspace `fuzz/` | Roadmap M2 требует fuzz построителя графа; cargo-fuzz — стандарт. `fuzz/` исключён из workspace, в граф `cargo deny`/аудита и в дерево пользователей не входит. Тот же оракул гоняется в proptest на Windows, где libFuzzer без cargo-fuzz не линкуется | 2026-10-13 |
| 21 | Бенчи `pragma_graph` | `criterion` (и с ним `alloca`, #17) — также dev-зависимость `pragma_graph` | Граф кадра в горячем пути (CONTRIBUTING: бенчмарк обязателен); те же условия, что в #17 | 2026-10-13 |
| 22 | Ресурсы графа | `Resources`: значение на тип в `RwLock`-слоте, доступ в кадре через `try_read`/`try_write`; `run(&mut self, …, &mut Resources)` | Без `unsafe`: граф доказывает непересечение доступа при сборке, поэтому блокировки не ждут, а занятый слот — ошибка `BorrowConflict` вместо гонки. `&mut` исключает параллельный кадр того же графа и чужие заимствования ресурсов во время кадра | 2026-10-13 |
| 23 | I/O-модель async | Без реактора: синхронный I/O (`std::fs`) — в ограниченном blocking-пуле `pragma_async` (`Executor::unblock`). Потоки по требованию до `blocking_threads` (4), поставленных задач — не больше `blocking_capacity` (1024), сверх лимита — сразу `AsyncError::Overloaded`. Blocking-задача — `Runnable` из `async-task`; ожидающий future будит сам `async-task` | Файловый I/O на Windows и Linux синхронный; IOCP/io_uring — платформенный `unsafe`-код и реактор ради выигрыша, которого у загрузки ассетов нет. Отдельные потоки — чтобы долгий `read` не занимал воркеры кадра; лимит очереди — выделение, размер которого задаёт вход, только под лимитом (reliability §1). Переполнение не блокирует вызывающего (кадр). Сброс исполнителя отменяет невзятые задачи и `join`-ит потоки; выполняющиеся дорабатывают — синхронный вызов не прервать | 2026-10-14 |
| 24 | Планирование async в пул | `pragma_jobs::Spawner`: `Weak` на пул + `spawn_detached(priority, f)`. `Runnable` уходит в пул как `Job::Boxed` с `Background`. После начала остановки пула задача сбрасывается (`Cancelled`); гонку с уже остановленным пулом закрывает флаг `stopped` + пара `fence(SeqCst)` с `Drop` | `pragma_jobs` не зависит от `async-task`. `Weak` разрывает цикл «очередь пула → `Runnable` → функция планирования → пул». Сброс `Runnable` — штатная отмена в `async-task`, ожидающий получает `Cancelled` вместо зависания. В режиме `Drain` фоновая задача, которая всё время перепланируется, не держит остановку пула бесконечно. `Box` на каждое планирование (~90 нс на Windows) приемлем для фоновых задач — горячий путь кадра его не использует | 2026-10-14 |
| 25 | Блокирующее ожидание async | `AsyncHandle::wait` из работы пула (воркер или внешний поток внутри `scope`/`join`, т. е. и кадр графа) сразу возвращает `AsyncError::WouldBlock`; мост в кадр — `poll_ready()` | Правило «никакого `block_on` в задачах кадра» проверяется машиной, а не ревью: на одном воркере такое ожидание повесило бы пул (фон исполняют только воркеры), на многих — задержало бы кадр. Проверка — `Spawner::in_pool_context` (TLS воркера, без аллокаций) | 2026-10-14 |
| 26 | Вертикальный срез `frame_sim` | Крейт `examples/frame_sim` — член workspace, слой 5 в `layers.toml`, `publish = false`, зависит только от фасада `pragma_core`. Фоновая загрузка применяется на заранее известном тике (`load_apply_tick`): готовая раньше — ждёт в буфере, опоздавшая — главный поток дожидается её между кадрами | Пример проходит те же линты, аудит слоёв и тесты, что и библиотека, и вызывается в CI как `cargo run -p frame_sim -- --verify 1,4`. Применение на фиксированном тике делает хеш независимым от момента завершения I/O, не исключая загрузку из хеша; `--verify` проверяет оба пути (успела / не успела) | 2026-10-14 |
