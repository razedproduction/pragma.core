# Roadmap pragma.core

Принцип: **вертикальный срез раньше ширины**. Уже к M3 пример `frame_sim` проходит через все слои:
пул → граф кадра → async-загрузка → детерминированный результат. Каждую следующую веху проверяем
на нём, а не на изолированных микротестах.

## M1 — Job system (0.1.0)

**Цель:** пул, на котором можно параллелить реальную работу кадра без дедлоков и потерь паник.

`pragma_sync`
- [ ] `Parker`/`Unparker` для сна воркеров (адресное пробуждение, без потерянных wakeup)
- [ ] `AtomicCounter`, на котором ждут задачи («ждать счётчик до нуля» вместо хэндла на каждую задачу)
- [ ] loom-модели: латч, парковка, счётчик

`pragma_jobs`
- [ ] `ThreadPool::new(PoolConfig) -> Result`, именованные потоки, корректный `Drop` (join всех потоков)
- [ ] Work-stealing: локальные `crossbeam_deque::Worker` + `Injector` + кража у случайной жертвы
- [ ] `spawn` → `JobHandle<T>` с `join() -> Result<T, JobError>`
- [ ] `join(a, b)` с help-while-wait; вложенный `join` на 1 воркере не дедлочит
- [ ] `scope(|s| ...)` с заимствованием данных (без `'static`)
- [ ] `parallel_for` / `parallel_for_chunks` с `Grain::{Auto, Fixed(n)}`; детерминированная редукция
- [ ] Перехват паник → `JobError::Panicked { job, message }`
- [ ] Приоритеты `Frame` / `Normal` / `Background` + лимит воркеров для `Background`

Тесты и бенчи
- [ ] proptest: `parallel_for` равен последовательному циклу; вложенные `scope` на случайной глубине
- [ ] Стресс (`#[ignore]`, в CI ночью): 10⁷ мелких задач, случайные паники, 1..2N воркеров
- [ ] `criterion`: spawn/join overhead, `parallel_for` на 10⁶ элементов, сравнение с `rayon`

**Готово, когда:** всё выше зелёное на Windows и Linux; накладные расходы spawn+join ≤ 2× от
`rayon::join`; при панике в задаче процесс не падает и ничего не виснет; `Drop` пула не оставляет потоков.

## M2 — Граф кадра (0.2.0)

- [ ] `FrameGraph::builder()`: задачи с объявлением `reads::<T>()` / `writes::<T>()` и явным `before`/`after`
- [ ] `build()`: циклы → `GraphError::Cycle`, неявный конфликт → `AmbiguousOrder`, неизвестная зависимость → ошибка
- [ ] Стабильная топосортировка; `run()` без аллокаций в установившемся режиме
- [ ] Хранилище ресурсов с безопасным раздельным доступом (типизированные слоты, проверка заимствований при сборке графа)
- [ ] Вложенный параллелизм: задача графа может вызвать `parallel_for`
- [ ] Экспорт графа в DOT/Mermaid для отладки
- [ ] Fuzz: произвольные описания графа → либо ошибка, либо корректный порядок
- [ ] CI: `cargo hack --each-feature`

**Готово, когда:** граф из ~50 задач строится один раз и исполняется за кадр без аллокаций;
любой конфликт без порядка ловится в `build()`.

## M3 — Async-задачи и вертикальный срез (0.3.0)

- [ ] Executor на `async-task`: `spawn_async(fut) -> AsyncHandle<T>`, планирование в пул с приоритетом `Background`
- [ ] Blocking-пул для синхронного файлового I/O (ограниченный размер)
- [ ] Отмена через drop хэндла, паника → `AsyncError::Panicked`
- [ ] Мост в кадр: `poll_ready()` / канал результатов, без `block_on` в задачах кадра
- [ ] **Пример `examples/frame_sim`**: headless-цикл с фиксированным шагом, 100k «сущностей»,
      граф из 5–10 систем, фоновая «загрузка» через async, хеш состояния на каждом тике
- [ ] `frame_sim` запускается в CI на N тиков и сверяет хеш на 1 и N воркерах

**Готово, когда:** `frame_sim` стабильно работает в CI на обеих ОС, хеш совпадает.

## Вне скоупа (пересматривается только через DECISIONS.md)

- ECS, рендер, окно/ввод, App/плагины, сеть: это задачи движков поверх ядра
- wasm / macOS / мобильные: API их не исключает, но поддержка — отдельная веха после 1.0
- Файберы/корутины на своих стеках: много `unsafe` и платформенного ассемблера; help-while-wait решает ту же проблему
- Свои lock-free структуры вместо crossbeam (DECISIONS #5)
- Tracy (C++): только за feature-флагом и по отдельному решению

## Риски

| Риск | Митигирование |
|---|---|
| Дедлоки во вложенных `join`/`scope` | help-while-wait по построению; стресс-тесты на 1 воркере |
| Потерянные пробуждения при парковке | loom-модели до мержа; таймаут-страховка при парковке |
| `scope` с заимствованиями требует `unsafe` (стирание лайфтайма) | Изолировать в `pragma_sync`, Miri; изучить подход `std::thread::scope`/rayon |
| Фоновые задачи вытесняют кадр | Лимит воркеров для `Background`, бенч «кадр под нагрузкой» |
| Рост скоупа (ECS «раз уж ядро») | Раздел «Вне скоупа» + DECISIONS #1 |
